Specification-driven development

From the first idea to running code - specified, gated, traced.

TomSpecs is a process for building software with AI agents. The specification is a typed object model, not prose: AI fills it, people decide at eight quality gates, and the code generated from it cites the specification sections it comes from.

The methodGet startedThe tools

Why specifications first

An AI writes code quickly, and just as quickly writes the wrong code. TomSpecs moves the decisions into documents that a person reviews and a machine can check. The code that follows is the consequence of an agreed specification, not of a prompt, and where the specification is silent the process stops and asks instead of letting the generator guess.

MODEL AS TRUTH

Typed specification documents

Fourteen document types, each a tree of sections with stable ids, typed forms and lists. Stored as YAML or Markdown, validated on three tiers, edited through the model.

AI-DRIVEN, HUMAN-GATED

Eight phases, eight gates

AI agents produce and review the work in pairs - a progress role and an independent quality role. A phase ends only when its gate passes; at G7 a human sign-off is mandatory.

CODE AS SPEC

A skeleton before the code

CodeSpecs turns the specification into an application that compiles but does not run yet: screens, forms, APIs, tables and rules, each declaration back-linked to its source section.

TEST-FIRST

Tests before implementation

The test suite is derived from the skeleton and the specification before any business code exists. Implementation is done when those tests pass.

Eight phases

Each phase has defined inputs, activities, outputs and a quality gate. A failed gate sends the work back; a defect found later re-opens the phase it came from. Details on the method page.
